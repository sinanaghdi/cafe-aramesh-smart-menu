# Café Aramesh Smart Menu — Roadmap

هر فاز باید معیارهای پذیرش و CI مربوطه را پاس کند. فازهای محصول به‌ترتیب و بدون تغییر مستقیم روی `main` توسعه می‌یابند.

## فاز ۰ — زیرساخت
- [x] PLAN.md و تصمیم‌های فنی
- [x] اسکلت FastAPI و React/Vite/TypeScript با RTL و فونت Vazirmatn
- [x] مدل دادهٔ چندکافه‌ای و مهاجرت اولیه
- [x] seed تکرارپذیر با ۲۵ محصول، تگ، ۵ دسته و ۸ میز
- [x] Docker Compose، CI، Dependabot، مستندات و قالب‌های مشارکت
- [x] بررسی اجرای واقعی Compose و seed در CI

## فاز ۱ — منوی مشتری و تأیید گارسون
- [x] منوی مشتری متصل به API و QR میز
- [x] سبد درخواست با قیمت و مبلغ نهایی محاسبه‌شده در سرور
- [x] نشست ناشناس مشتری با کوکی HTTP-only و digest نشست در دیتابیس
- [x] کد تأیید CSPRNG، HMAC، انقضا، یکتایی فعال، تک‌مصرفی و قفل پس از تلاش‌های ناموفق
- [x] ورود staff با Argon2، JWT دسترسی کوتاه‌مدت و refresh token چرخشی
- [x] state machine و رد انتقال غیرمجاز
- [x] صف کارکنان و SSE؛ پاسخ staff فاقد مبالغ و آمار فروش
- [x] audit log برای ایجاد، تأیید، لغو و انقضا
- [x] تست‌های واحد/API برای سفارش، امنیت نقش، کد، انقضا و refresh token
- [ ] بررسی نهایی و ادغام PR این فاز

## فاز ۲ — استادی‌مود و باشگاه مشتریان
- [ ] قوانین Merchant برای مدت، ساعت، مبلغ حداقل، محصول الزامی و ظرفیت همزمان
- [ ] ووچر زمان‌دار Mock فقط پس از تأیید سفارش؛ شمارش معکوس و هشدار ۱۰ دقیقه‌ای
- [ ] قابلیت تمدید واجد شرایط پس از سفارش جدید
- [ ] SmsProvider با OTP آزمایشی، رضایت صریح و حذف حساب
- [ ] امتیاز، سطح‌های برنز/نقره/طلا، پاداش و تاریخچه

## فاز ۳ — NLP فارسی و کمبوی هوشمند
- [ ] نرمال‌سازی فارسی/عربی، ارقام، نیم‌فاصله و لغت‌نامه مترادف‌ها
- [ ] رتبه‌بندی مبتنی بر تگ محصول و توضیح چرایی پیشنهاد؛ سؤال شفاف‌ساز برای درخواست مبهم
- [ ] لاگ ناشناس کوئری‌های بی‌پاسخ
- [ ] موتور تست‌پذیر `BOOST_BESTSELLER` و `PUSH_SLOW_MOVER` بر اساس دادهٔ سفارش، حاشیه سود، هم‌خریدی، ساعت و سبد
- [ ] AI اختیاری و fallback قاعده‌محور؛ نمایش کمبو تنها پس از تأیید Merchant

## فاز ۴ — پنل Merchant و آنالیتیکس
- [ ] مدیریت دسته‌ها، محصولات، گزینه‌ها و کمبوها
- [ ] قوانین استادی‌مود و باشگاه و مدیریت حساب‌های کارکنان
- [ ] KPI روزانه/هفتگی/ماهانه، تاریخ شمسی، مقایسه دوره، نمودار و خروجی CSV

- [ ] AI Insights با شواهد و اطمینان؛ تأیید/رد صریح و fallback آماری
- [ ] همه endpointهای تحلیلی فقط برای Merchant

## فاز ۵ — سخت‌سازی و انتشار
- [ ] پوشش حداقل ۷۰٪ منطق دامنه و E2E سبک Playwright
- [ ] تست IDOR، tenant isolation، rate-limit و تلاش مجدد
- [ ] بررسی دسترس‌پذیری، RTL، امنیت کوکی/توکن و performance روی شبکه محدود
- [ ] لاگ ساختاریافته، سیاست نگهداری داده، پشتیبان‌گیری و راهنمای استقرار
- [ ] بررسی نهایی migration، secrets و CORS عملیاتی

## توسعه‌های آینده — فقط نقاط توسعه، نه پیاده‌سازی
سفارش آنلاین، ایجنت AI و دستیار پشتیبانی AI در MVP ساخته نمی‌شوند. Feature flagهای آن‌ها پیش‌فرض خاموش می‌مانند و به معنی قابلیت فعال یا پیاده‌سازی‌شده نیستند.

## قواعد پذیرش کل محصول
- سفارش از QR به تأیید حضوری گارسون می‌رسد و کد کوتاه امن/منقضی‌شونده دارد.
- ووچر استادی‌مود فقط پس از تأیید معتبر صادر می‌شود.
- AI هیچ تغییر تجاری را خودکار اعمال نمی‌کند.
- تحلیل Merchant از دادهٔ واقعی سفارش‌ها می‌آید؛ staff هیچ آمار فروش یا درآمدی دریافت نمی‌کند.
- `docker compose up --build` کل سیستم را بالا می‌آورد و seed می‌کند؛ CI سبز است.
